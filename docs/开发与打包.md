# 开发与打包

面向二次开发与自行构建，产品用法不在这里 —— 见 [使用指南](使用指南.md)。

## 快速开始

无需安装任何依赖，电脑上有 Python 3 即可运行：

```bash
python scripts/notes_app.py
```

启动后会在项目根目录的 `data/` 下自动创建 `notes_data.db` 数据库文件。

## 目录结构

```
local-notes/
├── scripts/            # 全部源码
│   ├── notes_app.py      # 入口 + NotesApp 核心（组合 UI / 动作两个 mixin）
│   ├── store.py          # 数据层：SQLite 读写、全文检索、保存失败兜底（不依赖 tkinter）
│   ├── backup.py         # 备份格式：导出编码 / 导入解码 / 合并与去重（纯函数，不依赖 tkinter）
│   ├── md_conv.py        # 纯文本规则：markdown 前缀、列表缩进、网址 / 时间函数识别（不依赖 tkinter）
│   ├── secret.py         # 笔记加密：PBKDF2 派生 + CTR 加密 + HMAC 认证（不依赖 tkinter）
│   ├── theme.py          # 外观层：字体、主题色读取、配色
│   ├── dpi.py            # DPI 层：DPI 感知、全局缩放比、px()/fx() 换算
│   ├── widgets.py        # 控件层：自绘按钮 / 滚动条 / 菜单 / 代码块 / 链接小窗
│   ├── app_ui.py         # 界面层：布局、渲染、刷新、交互（UIMixin）
│   ├── app_actions.py    # 动作层：新建 / 删除 / 导入导出 / 编辑排版 / 加密（ActionsMixin）
│   ├── exporter.py       # 导出层：把正文还原成纯文本 / Markdown 的行模型（不依赖 tkinter）
│   ├── mention.py        # @ 关联笔记：触发词识别、候选排序（多词 AND，不依赖 tkinter）
│   ├── mention_ui.py     # @ 候选浮层：搜索框 + 自绘列表（不 grab；框内搜索 / 正文打字双路过滤）
│   ├── sql_fmt.py        # SQL 格式化：按子句关键词断行（纯字符串，不依赖 tkinter）
│   ├── punct.py          # 格式化前的中文标点归一化（纯字符串，不依赖 tkinter）
│   ├── calc.py           # `$` 公式计算：AST 白名单 + Decimal（纯字符串，不依赖 tkinter）
│   ├── alarm.py          # 任务提醒：时间解析 / 到点判定 / 悬浮文案（纯字符串，不依赖 tkinter）
│   ├── updater.py        # 检查更新 / 下载 / 校验 / 安装
│   ├── version.py        # 版本号唯一来源
│   └── pdf_export.py     # PDF：GDI 排版成页面位图 + 纯 Python 拼 PDF（GDI 部分仅 Windows）
├── data/               # 本地数据（首次运行自动生成 notes_data.db；保存失败时另有 pending_*.json 兜底快照）
├── docs/               # 文档：使用指南 / 快捷键 / 数据与备份 / 开发与打包
├── icon/               # 图标源图：app_icon.png（512px）+ 顶栏各按钮的 200px 线条图
│   ├── px/<size>/        #   预渲染的各档成品（运行时零缩放直接取，见「图标」一节）
│   └── app_icon.ico      #   打包/运行时用，由 target/gen_icons.py 逐档组装
├── images/             # README 与文档截图
├── target/             # 打包脚本与产物：build.bat / build.py / run.bat、dist/、build/
├── tests/              # 数据层 / 文本规则 / 加密的最小测试（标准库 unittest）
├── README.md
└── LICENSE
```

源码运行读「项目根 `data/`」，打包成 exe 后读「exe 旁 `data/`」，数据始终随程序带得走。

## 分层与依赖

依赖方向是单向的：

```
store  ←  theme  ←  widgets  ←  app_ui / app_actions  ←  notes_app
```

纯逻辑模块（`store` / `backup` / `md_conv` / `secret` / `exporter` / `mention` / `sql_fmt` / `punct` / `calc` / `alarm`）不依赖 tkinter，可以脱离界面单独测试；`pdf_export.build_pdf()` 也是纯函数，只有 GDI 排版那一段依赖 Windows。

## 技术栈

- **语言**：Python 3
- **GUI**：Tkinter（标准库，零外部依赖）
- **数据**：SQLite3（标准库），全文检索用 FTS5 + trigram 分词（环境不支持时自动回退 LIKE）
- **加密**：PBKDF2-HMAC-SHA256 派生密钥 + HMAC 认证的 CTR 加密，同样只用标准库（`hashlib` / `hmac` / `secrets`）
- **PDF**：`ctypes` 调 `gdi32` 排版成位图，`zlib` 压缩后由纯 Python 拼装
- **测试**：`tests/`，标准库 unittest，无第三方依赖

## 运行测试

数据层、文本规则和加密都不依赖界面，用标准库 unittest 即可验证（SQLite 读写、搜索通配转义、备份的编码解码与合并去重、markdown 前缀识别、口令与密文完整性、导出与 SQL 格式化的输出等）：

```bash
python -m unittest discover -s tests
```

也可以单独跑某一个文件，例如 `python tests/test_store.py`。

## 图标

界面里的图标**不在运行时缩放**：`target/gen_icons.py` 会把 `icon/` 下的源图预渲染成每一档精确尺寸，放进 `icon/px/<size>/`，运行时 `widgets._icon_photo()` 只做「按尺寸取图 + 按皮肤染色」。

这么做的原因很具体：源图是 200×200 的线条图，笔画只有 12~18px 宽，而顶栏要的是 16px —— 200→16 是 12.5 倍，一条线缩完只剩 1.2px。Tk 只有**整数倍最近邻**采样，在运行时缩就是断断续续的灰点；交给 PIL 能好一些，但项目承诺「有 Python 就能跑」，源码运行不保证有 Pillow。把缩放固定在生成那一步，运行环境有没有 Pillow 看到的都是同一张图。

```bash
python target/gen_icons.py          # 重新生成 icon/px/ 与 app_icon.ico
python target/gen_icons.py --check  # 只检查产物是否齐全（缺了会列出来）
```

几个约定：

- **线条图标**（db / about / create / github / issue / note / code / notice）先按 alpha 包围盒裁边，缩放后对 alpha 做一次增益 —— 细线被平均掉的墨量补回来，否则 16px 上就是一缕灰雾。
- **要染色的五张**（create / github / issue / note / code）在 `icon/px` 下存的是**白色掩膜**：形状和抗锯齿边都在 alpha 里，运行时只换 RGB。改这几张的源图不用管颜色。
- **code.png 的源图是脚本画的**（`python target/make_brace_icon.py`）。花括号没有设计稿可画，只有比例和粗细要调；更重要的是 Tk 8.6 的 canvas 线条**没有抗锯齿**，运行时用 `create_line` 画 16px 的花括号，整枚只有 2 个灰阶、腰部和斜线全是台阶。改成「超采样画好再缩」之后有几十个中间灰阶，边缘才平滑。工具栏按钮用 `RoundButton(icon_img="code.png")` 贴图；位图缺失时自动退回原来的矢量画法。
- **app_icon 在 32px 及以下**走另一套参数（裁边 + 提饱和度 / 对比度 + 锐化）。512px 的拟物图直接缩到 16px 只剩一团米色，提饱和之后铅笔才认得出；这是「同一张图在不同尺寸下需要不同处理」的典型例子。
- **app_icon.ico** 逐档取自上面的成品，不用 Pillow 的 `save(sizes=[...])` —— 那是从 512 原图再缩一遍，16/24/32 又会糊回去。
- **主题色卡的圆走运行时抗锯齿栅格化**（`widgets.AAImage`）：Tk Canvas 不抗锯齿，`create_oval` 和椭圆描边在 34px 上必然是台阶 + 一圈粗细不均的方块。改用 SDF + 4×4 子采样算覆盖率混色，一次性 `PhotoImage.put` 贴到 Canvas。之所以不像图标那样预渲染 PNG：圆内是六套主题各自的固定三色，环 / 光晕 / 底板又随当前主题变，组合数随主题数平方增长，且每个 DPI 档都要一套资源；运行时算既零依赖也免维护。位图按状态缓存，`<Enter>/<Leave>` 只重贴不重算。

加一张新图标：把源图放进 `icon/`，在 `gen_icons.py` 的 `LINE_ICONS` 里登记（缩放方式 + 是否染色），然后跑一次生成脚本。`tests/test_icons.py` 会检查「程序用到的每一档都存在且尺寸精确」，漏生成会直接测试失败 —— 否则运行时只会**静默**退回原图缩放，肉眼很难发现。

> ⚠️ 这套机制解决的是「图标本身糊」。Windows 缩放比不是 100% 时，还要靠 DPI 层
> 让窗口按物理像素渲染，否则整张窗口会被 DWM 位图拉伸，任何图标方案都救不了。
> 见下方「高 DPI」。

## 打包成 exe

`target/` 目录下已备好打包脚本，无需手写命令：

- 双击 `target/build.bat`（或命令行 `python target/build.py`）→ 自动安装 PyInstaller / Pillow、预渲染图标并打包
- 产物在 `target/dist/素笺/素笺.exe`，**双击即可打开，目标机器无需再装 Python**
- 数据库生成在 exe 旁的 `data/` 目录，整目录拷贝即可带着数据走、方便备份
- 只想从源码调试运行，可双击 `target/run.bat`（等同于 `python scripts\notes_app.py`）

## 高 DPI

界面在 125% / 150% / 200% 下同样锐利，靠的是**两件事一起做**：

1. **声明 DPI 感知**（system DPI aware）：`dpi.init()` 在创建任何 Tk 窗口之前调
   `shcore.SetProcessDpiAwareness(1)`（老系统回退 `SetProcessDPIAware()`）。不声明的话，
   Windows 会把程序按 100% 画好的整张窗口位图拉伸 1.25/1.5 倍 —— 文字、边框、图标一起变软，
   那层模糊发生在 DWM，交出去的位图再清晰也没用。
2. **全局像素缩放**：所有按设计稿写死的像素常量（顶栏高度、图标画布、侧栏/列表宽度、
   `padx`/`pady`、画布坐标、线宽）都经 `dpi.px()` 乘上当前缩放比；字体是点值，Tk 自己会缩放。

只做第 1 件会让界面缩成一小块（字变大、容器没变），只做第 2 件则依旧被系统拉伸，
所以两件必须同时存在。实现在 `scripts/dpi.py`：

| 函数 | 用途 |
| --- | --- |
| `dpi.SCALE` | 当前缩放比，1.0 = 100%；在 `init()` 里定一次 |
| `dpi.px(n)` | 设计稿像素 → 物理像素（**四舍五入到整数**） |
| `dpi.fx(n)` | 同上但保留小数，给线宽这类量用 |
| `dpi.scale_canvas(cv)` | 把已按 1× 逻辑坐标画好的画布整体放大（文件夹小图标用） |
| `dpi.apply_tk_scaling(root)` | 让 Tk 的「点 → 像素」与 `SCALE` 对齐 |

### 为什么 `px()` 必须落回整数

Tk 画布不做抗锯齿。0.5px 的偏移会把 1px 的描边摊成两条半透明灰线，细边框和图标外框
最先遭殃 —— 那是「糊」的另一半来源。所以容器尺寸、坐标一律取整；只有描边宽度用
`fx()`，让它在高倍率下真的变粗，而不是永远 1px。

### 导入顺序是硬约束

`SCALE` 必须在**模块导入期**就定好，因为 `widgets.py` / `app_ui.py` 里的常量是
`TOP_BAR_H = dpi.px(30)` 这种一次性求值，而且 `app_ui` 里还有
`from widgets import TOP_BAR_H` 这样的**名字拷贝**。等 Tk 建好再改 `SCALE` 已经晚了。

所以 `notes_app.py` 顶部是这样：

```python
import dpi
dpi.init()          # 必须在 any tkinter / widgets / app_ui 导入之前

import tkinter as tk
from widgets import ...
```

新增界面代码时，凡是「像素」都要过 `dpi.px()`；点值字号、字符数宽度（`Label(width=8)`）
不用。自绘控件如果坐标是按逻辑格写死的，用 `dpi.scale_canvas()` 整体放大一次；
如果坐标已经由缩放后的常量推出来，**不要**再调它 —— 会放大两次。

### 图标档位

`icon/px/` 不是只出 1×/2×，而是按 Windows 的缩放档逐档渲染：
每个逻辑尺寸 × `(1.0, 1.25, 1.5, 1.75, 2.0, 2.25, 2.5, 3.0)`。
运行时请求 `dpi.px(16)`，在 150% 下正好是 24 —— 命中一张**精确尺寸**的成品，
不重采样。`tests/test_icons.py` 会把「每个图标 × 每个档位」都断言一遍，
`gen_icons.plan()` 与测试共用同一份档位表，漏一档直接测试失败。

### 验证方式

本机是 100% 时也能模拟高 DPI（字号会一起放大，截出来就是真实比例）：

```bash
set SUJIAN_UI_SCALE=1.5 && python scripts\notes_app.py
```

不设环境变量时按系统 DPI 取 `GetDpiForSystem() / 96`，并夹在 `[0.75, 4.0]` 之间。

### 两栏宽度按设计稿像素存

拖过分隔条后 `settings["side_w"]` / `["list_w"]` 存的是**除以 SCALE 的设计稿宽度**，
读回来时再乘当前缩放。这样同一份数据在 125% 和 200% 的机器上都还原成同样的视觉比例；
存物理像素的话，换台机器一打开，两栏要么挤成一条缝、要么把正文推到屏幕外。

### 已知边界

没有做 per-monitor 感知：把窗口拖到另一块**不同缩放比**的副屏时，系统会做一次位图
缩放，副屏上会略软；主屏始终锐利。要做到副屏也锐利，得在 `WM_DPICHANGED` 里把整棵
控件树按新比例重建 —— 对 Tk 这种「一套比例画到底」的界面改动量不成比例，暂不做。

## 关于 PDF 导出

零依赖是硬约束，而 PDF 里要让中文像样只有两条路：

1. **嵌 TrueType 子集** —— 得自己实现 `glyf / loca / cmap / hmtx` 的子集化；不做子集就得把整套 10MB 的雅黑塞进每一份导出，一条便签变成 13MB 的 PDF。
2. **先把字画成图，再把图画进 PDF** —— GDI 是系统自带的（`ctypes` 直接调，不算第三方），字体、字号、行距用的就是屏幕上那一套。

这里走第 2 条：`ctypes` 调 `gdi32` 在内存 DIB 上排一遍版（H1 1.35 倍 / H2 1.15 倍、行高 1.7、中文折行带行首禁则、列表与待办画几何图形而不是字符），144dpi 出 A4 位图，`zlib` 压缩后按 PDF 的图片 XObject 逐页拼装（`build_pdf()` 是纯函数，脱离 Windows 也能单测）。

代价：**PDF 里没有文字层**，复制和全文检索取不到字；换来的是零依赖、字形与界面一致、一页约 100–300KB。要文字可选，只能接受引入字库子集化或第三方库。
